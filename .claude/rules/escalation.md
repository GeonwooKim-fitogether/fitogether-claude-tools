# 에스컬레이션 규칙 — 언제 멈추고 언제 계속하나

> 한 줄 요지: **사람은 전달자가 아니라 최종 승인자다.** 작은 결정은 Claude가 기본값을 채택해 계속 진행하며 결정 큐에 1행만 남기고, 아래 관문 트리거에 해당하는 결정만 즉시 사람에게 카드 한 장으로 올린다.

작은 결정마다 사람에게 물으면 사람의 시간이 전달·클릭에 소모되고, 반대로 큰 결정을 묻지 않고 지나가면 사고가 된다. 이 규칙은 그 경계를 한 곳에서 정한다. 엔진의 크기를 정하는 [판돈 규칙](./stake-calibration.md)과 형제 규칙이다 — 판돈 규칙이 "얼마나 큰 엔진을 켜나"를 정하면, 이 규칙은 "언제 사람을 부르나"를 정한다.

## 1. 실행 분류 매트릭스 — 되돌리기 비용 × 영향 범위

| 결정의 성격 | 행동 |
|---|---|
| 명백히 옳은 것 (이름 정리, 작은 수정) | 즉시 실행. 기록 불필요 |
| 애매하지만 일반적 관행이 있는 것 | 관행을 채택하고 진행 + 결정 큐 1행 |
| 애매하고 트레이드오프가 있으나 되돌리기 쉬운 것 | 기본값을 채택하고 진행 + 결정 큐 1행 (보고 시 검토) |
| 되돌리기 어렵거나 영향이 넓은 것 | **사람 관문** — 아래 트리거 확인 후 §3 카드로 즉시 올림 |

기본값을 고를 때의 우선순위: 이 팀의 규칙(`.claude/rules/`) → 그 저장소의 CLAUDE.md·설계 문서 → 언어·프레임워크의 일반 관행 → Claude의 일관된 판단. 같은 상황에서 다른 답을 내지 않는다.

## 2. 사람 관문 트리거 — 하나라도 해당하면 즉시 올린다

1. **보안** — 인증·인가·RLS·시크릿. 잘못되면 사고다.
2. **라이브 데이터베이스** — 실환경 데이터·구조를 바꾸는 모든 것 (db-write-permission 규칙의 열쇠 절차가 이 관문의 강제 장치다).
3. **되돌리기 어려운 구조 선택** — 프레임워크·핵심 라이브러리·데이터 모델의 방향.
4. **범위 초과** — 요청받은 범위를 의미 있게 넘어서는 작업 (communication 규칙 7-8과 같은 정신).
5. **비용 발생** — 유료 서비스 도입·플랜 격상.
6. **공개·배포** — main 머지, 실환경 노출, 외부 공유.

이 여섯이 아닌 결정은 사람 관문이 아니다 — 진행하면서 결정 큐에 기록한다.

## 3. 결정 카드 — 올릴 때는 한 장으로 끝나게

사람에게 결정을 올릴 때는 조각조각 묻지 않고 아래 한 장으로 올린다. 카드는 **읽는 사람이 위로 스크롤하지 않고 그 자리에서 답할 수 있어야 한다** (맥락 재진술 포함).

```markdown
## 결정 요청 — <한 줄 제목>
- **트리거**: <§2의 몇 번, 이름>
- **결정 사항**: <무엇을 정해야 하나, 한 단락 — 필요한 맥락은 여기 재진술>
- **옵션**: A / B / C (각 1줄 + 트레이드오프)
- **추천**: <하나 + 사유 1줄>
- **무응답 시 기본 행동**: <기본값, 또는 "결정 없이는 진행 불가">
- **되돌리기 비용**: 낮음 / 중 / 높음
```

응답을 기다리는 동안 **그 결정에 의존하지 않는 다른 작업은 계속 진행한다.** 차단되는 것만 멈춘다.

## 4. 결정 큐 — 기록하고 계속 진행한다

결정 큐는 차단기가 아니라 **작은 결정의 누적소**다. 진행 중 채택한 기본값을 아래 형식으로 보고(또는 작업 로그)에 쌓고, 작업 보고 시점에 묶어서 한 번 검토받는다. `/sysreport`가 파트 보고를 걷을 때 이 큐가 결정 큐 입력이 된다.

| 결정 내용 | 채택한 기본값 + 사유 | 되돌리기 | 검토 시점 |
|---|---|---|---|
| 예: 플랜 코드 대소문자 | 소문자 — DB 컬럼 관행 | 쉬움 | 이번 보고 |

## 5. 위반 신호 — 이 규칙이 잘 돌고 있는지 잰다

- 한 시간 작업에서 사람에게 짧은 결정을 3회 이상 물었다 → 분류가 너무 보수적이다. §1의 비차단 쪽으로 재조정한다.
- 사용자가 "그냥 알아서 해"를 반복한다 → 같은 신호다.
- 진행 중인데 결정 큐가 비어 있다 → 결정을 회피하고 사람에게 떠넘기고 있을 가능성. 
- 반대로, §2 트리거에 해당하는 것이 큐에 들어가 있다 → 즉시 카드로 꺼내 올린다. 관문을 큐로 우회하는 것이 이 규칙의 가장 나쁜 위반이다.

## 적용 범위

- 모든 저장소의 모든 세션에 적용된다. 개별 관문 장치(db-write-permission의 열쇠, merge-gate)는 이 규칙의 특수화이며, 충돌하면 더 구체적인 그 장치가 이긴다.
- 단일 원본은 창고(Template-repository)의 `.claude/rules/escalation.md`다. 여기서만 고치고, 동기화 봇이 내려보낸다.
