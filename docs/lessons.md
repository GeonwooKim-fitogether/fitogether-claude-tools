# Lessons — Template-repository (창고)

> 작업 중 발견한 체계(규칙·스킬·게이트·절차)의 어색함을 3줄로 기록한다.
> 규약은 [`.claude/rules/lessons-backport.md`](../.claude/rules/lessons-backport.md).
> 기록은 차단기가 아니다 — 적고 계속 진행한다. 창고 반영은 수확 → 4분류 → 사람 승인 뒤에만.

## 누적

### 2026-08-26 — 티어 판정에 "전담자 유무 확인"이 없다
- **증상**: CEO 브리프 제작을 메인 세션이 직접(T0) 처리했는데, 문서 정제 전담 에이전트(doc-clarifier)가 있는데도 그것을 확인하는 절차가 판돈 규칙에 없어 전담자가 우회됐다. 결과물은 좋았으나 전담자의 규약이 적용됐는지 아무도 보증하지 못한다.
- **제안**: 판돈 규칙의 티어 판정 앞에 "이 일의 전담 에이전트·스킬이 이미 있는가"를 먼저 확인하는 한 줄 추가.
- **일반화**: 가능 — 전담자가 늘수록 어느 저장소에서든 같은 우회가 생긴다. (사례 1건이므로 규칙 격상은 보류, 규약대로 기록만.)

### 2026-08-26 — 동기화 봇 자신의 버전 드리프트를 재는 장치가 없다
- **증상**: career는 스킬만 내려받는 옛 봇, Geonwoo-LLM-Wiki는 존재하지 않는 경로를 바라보며 9회 연속 실패한 화석 봇이었는데, 수동 전파를 시도하기 전까지 아무도 몰랐다. `.github/workflows/`는 동기화되지 않으므로 이 드리프트는 구조적으로 재발한다.
- **제안**: 자산 그래프 검사(또는 주기 스윕)에 "하위 저장소의 sync-skills.yml이 창고 판과 같은가" 대조 한 줄 추가.
- **일반화**: 가능 — 봇이 있는 모든 하위 저장소가 같은 위험을 진다.

### 2026-08-26 — 워크플로 YAML을 파싱 검증 없이 커밋해 5회 연속 조용히 실패했다
- **증상**: `asset-graph.yml`의 스텝 이름에 따옴표 없이 콜론이 들어가(`name: 그래프 정합 검사 (창고: README 배선 포함)`) GitHub가 파일을 파싱하지 못했다. 실행은 0초·잡 0개로 끝나 5회 모두 실패했고, 정작 검사기는 지역에서 통과하고 있어 "검사가 돌아 통과했다"와 "검사가 아예 안 돌았다"가 보고에서 구분되지 않았다.
- **제안**: 워크플로 파일을 커밋하기 전에 YAML 파싱을 한 번 돌린다(`python3 -c "import yaml;yaml.safe_load(open(f))"` 한 줄). 나아가 자산 그래프 검사에 "워크플로 YAML이 파싱되는가" 한 축을 더할 수 있다.
- **일반화**: 가능 — 워크플로를 추가하는 모든 저장소가 같은 실수를 할 수 있고, 실패가 조용해서 더 위험하다.
